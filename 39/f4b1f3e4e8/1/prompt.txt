# N10 — Amend ADR 0032: per-persona display-only marker state

**Type:** `adr`. ADR 0032 settled `_active.persona` as a single string, last-write-wins, and
explicitly rejected richer persona state to avoid read-modify-write races. The persona fan-out (N11)
needs per-persona state, which reverses that decision — a real architectural change, settled and
plan-reviewed before any skill writes the new shape.

> **▶ On pickup — before N11:** record the amendment through the ADR discipline. Run the plan-review
> gate: this reverses a prior accepted decision on the shared supervisor↔pack boundary (ADR 0030 /
> 0032).
> **Blocks:** N11 — the persona drill-down must write against the settled shape, and the display-only
> invariant must hold before any skill writes it.

## What

Amend ADR 0032 so the pack may author a display-only **per-persona roster and state** alongside the
existing single `_active.persona`, while keeping every read non-gating (no advancement, halt, grade,
retry, exit-code, or stop-guard path may read it). The amendment settles the **race-free write rule**:
`exec:review` writes the full roster once on entry (all `queued`); the existing last-write-wins
`_active.persona` marks the running one; the renderer derives `done` for any persona before it in the
roster order — no per-member read-modify-write. Optional per-persona verdicts ride under separate keys
(`review.persona_verdicts.<name>`) so concurrent writers never share a key.

## Why

The assumption being tested: per-persona state can be display-only and race-free at once — a
write-once roster plus single-key verdicts avoids the read-modify-write contention that made ADR 0032
choose a single string, without making the supervisor decide on any of it. The rejected alternative
is a mutable shared `personas[]` array each sub-agent edits in place: that is exactly the race ADR
0032 rejected. Accepting this is the prerequisite for N11; until it lands, the persona contract is
unsettled and the single-string rule still forbids the fan-out.

## Completion

**Decision:** the pack may write a display-only per-persona roster (write-once, all `queued`) and
per-persona verdicts under separate keys; the renderer derives queued/running/done from the roster
order and the single `_active.persona`; no decision path may read any of it. Recorded as an amendment
to ADR 0032 with context and consequences, citing ADR 0030 and architecture §5, and naming the
enforcement: the import-guard (only the renderer module reads the new keys) and an NFR-3
fault-injection test on a malformed roster. The amendment states backward-compatibility — `handoff`
reads ignore unknown keys — and that an old pack writing no roster degrades to the single inline
persona. The ADR template discipline is not re-authored here; it lives in the ADR skill.

## Assumptions

* `exec-state.json` reads ignore unknown keys, so an additive roster and per-persona verdict keys are backward-compatible with `handoff.read*`. *(verified)*
* A write-once roster plus single-key per-persona verdicts avoids read-modify-write contention under a Claude-Code parallel persona fan-out. *(to-verify)*
* The display-only invariant stays enforceable by the import-guard once the new keys exist (only the renderer module reads them). *(to-verify)*

## Key Risks

* **Risk:** the roster or verdict keys are written in a shape that still races under parallel
  sub-agents, reintroducing the hazard ADR 0032 avoided. *Falsifier:* if any write needs to
  read-modify-write a shared key, the shape is wrong — keep the roster write-once and verdicts on
  per-name keys.
* **Risk:** "display-only" is asserted but a later change reads a persona key in a decision path,
  breaking the boundary. *Mitigation:* the amendment mandates the import-guard; N11 lands it, and
  review treats any decision-path read of the persona keys as a boundary violation.
