# Slice 1 — Override seam for the GraphQL URL + ADR

## What

drain-cycle's GraphQL URL becomes configurable via env var. An ADR records the chosen integration-test architecture and the rejected alternatives.

## Why

Without an override seam, every failure-mode test needs either a real Linear cycle or invasive monkey-patches. Both make the OKR's failure-mode suite cost-prohibitive to maintain. The ADR records the seam choice so the next reader (or agent) reuses it instead of re-deriving it.

## Assumptions

* The runlog directory honours `HOME` re-resolution.
* No code path outside `linear.py` bakes the `api.linear.app` URL.

## Key Risks

* `HOME` caches at module-load time and silently breaks tests under `monkeypatch.setenv`.
* The ADR ships after the foundation slices and drifts from what was actually built.

## Definition of Done

* Setting `LINEAR_API_URL` routes drain-cycle's GraphQL calls to that URL.
* A unit test confirms the override.
* The default URL is unchanged when the env var is unset.
* `docs/adrs/0001-integration-test-architecture.md` exists and is referenced from the design doc.
