# `drain-cycle grade-draft <issue>`: one-shot command writes per-ticket grade file with `status: draft`

## What

`drain-cycle grade-draft <issue>` produces a per-ticket grade file at `~/.drain-cycle/grades/<issue>.md` with `status: draft` and a pre-populated KR-check checklist drawn from the run-log entry for that issue.

## Why

Without this command, KR grading requires the operator to read raw run-log JSON and fill out the checklist manually. The draft file is the starting point the operator confirms or corrects — separating the data-pull step from the judgement step.

## Assumptions

* The grade file format is a markdown template with a `status:` field (values: `draft`, `confirmed`).
* The command reads from the run-log entry for the given issue.
* The command runs automatically on drain completion for verify-flow tickets AND can be run manually for retro-filling past tickets.

## Key Risks

* If the run-log entry is absent or incomplete, the command must error clearly rather than produce a misleading draft.

## Definition of Done

* `drain-cycle grade-draft <issue>` produces `~/.drain-cycle/grades/<issue>.md` with `status: draft` and a populated KR checklist from the run-log entry.
* Running the command a second time on the same issue overwrites the draft without creating duplicates.
* The command runs automatically on drain completion for verify-flow tickets.
* If the run-log entry is absent, the command exits with a clear error.
