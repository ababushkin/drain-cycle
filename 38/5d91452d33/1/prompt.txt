# Make stacking the default, with a push-to-main override

**Depends on:** [ABA-302](https://linear.app/ababushkin/issue/ABA-302/assemble-one-stacked-pr-per-repo-and-flag-what-needs-review).

## What

Stacked PRs become the default for every drained issue. A repo opts out via `push_to_main_repos` in `repos.yml`, and a whole run opts out via `--no-stack`; opted-out issues keep today's push-to-main behavior.

## Why

The owner wants stacking as the norm, but some repos — `drain-cycle` itself, whose `AGENTS.md` mandates push-to-main — must keep landing on `main`. The override keeps that path intact and the rollout reversible.

## How (mechanical)

* Add an optional top-level `push_to_main_repos: [<name>]` to `repos.yml`, following the backward-compatible `worktree_config_paths` pattern; parse and validate it in `repos.load` (reuse the validation style of `repos._parse_worktree_config_paths`) and surface it on the `Repos` dataclass (`drain_cycle/repos.py:65`).
* Add `--no-stack` to `drain_cycle/cli.py`.
* In the orchestrator, compute `stack = repo.name not in push_to_main_repos and not cli_no_stack`; thread it into `prompt.build(stack=…)`; skip the Ticket-302 stack-assembly step when `stack` is false.

## Acceptance criteria

- [ ] A repo listed in `push_to_main_repos` reproduces today's behavior exactly — agent pushes to `main`, no PR, no handoff. (test)
- [ ] `--no-stack` disables stacking for the whole run. (test)
- [ ] With no config and no flag, stacking runs by default. (test)
- [ ] `docs/repos.example.yml` shows the new `push_to_main_repos` key.
- [ ] `pytest` passes.
