<title>Watch mode: format stream-json in the pane instead of showing raw JSON</title>
<description>
## What

When drain-cycle runs in watch mode, the tmux pane currently shows raw stream-json scrolling by — one JSON event object per line. Make the pane show a human-readable rendering (assistant prose, tool calls, tool-result sizes, a done footer) while drain-cycle's parser keeps reading the unmodified stream-json off the FIFO.

The mechanism: insert a formatting filter on the pane-visible branch of the pipe only. The tee stage already splits the stream, so the FIFO branch (drain-cycle's parser input) stays byte-for-byte identical. The pane copy is routed through a formatter; the FIFO copy is not.

## Why

<issue id="f7e27c53-453e-4cf0-a7cf-59f6ed7bd486">ABA-339</issue> made the watch pane be the claude session (claude routed through tee into the FIFO), which fixed parse fidelity and removed the intermediate log file — but it regressed readability. The pane now shows raw stream-json because that is exactly what claude emits and the pane shows it verbatim. drain-cycle requires verbose stream-json output to track usage and cost and to detect breaches, so we cannot make claude emit prettier output; we have to format the operator's copy downstream.

The human-readable formatting logic already existed as the \_WatchWriter class that <issue id="f7e27c53-453e-4cf0-a7cf-59f6ed7bd486">ABA-339</issue> deleted (recoverable from history at commits df63bc4 and 9f5f707). The work is to bring that logic back as a stdin-to-stdout filter rather than a file writer — which also preserves <issue id="f7e27c53-453e-4cf0-a7cf-59f6ed7bd486">ABA-339</issue>'s no-intermediate-log-file property, since the formatter is a live pipe stage, not a file.

## How

* Add a small stdin-to-stdout filter (for example a python module run with -m, or a console entry point) that reads stream-json lines and writes the formatted, line-buffered rendering to stdout. Port the \_WatchWriter content-block handling (text, tool_use, tool_result, result) — but emit to stdout instead of an opened file, and drop the file handle.
* In \_open_watch_pane, append the formatter as a final stage of the pane pipeline after the tee. Resolve the interpreter explicitly (shlex-quoted sys.executable) and run it unbuffered or line-buffered so output appears live. The tee stays upstream of the formatter, so a formatter that fails or is absent cannot affect parse fidelity — the FIFO branch is independent.
* Keep graceful fallback: if the formatter cannot be launched, the pane is still usable (worst case it shows raw JSON again — never a crash, never a parser impact).
* Restore the formatter's unit tests (the \_WatchWriter tests deleted in <issue id="f7e27c53-453e-4cf0-a7cf-59f6ed7bd486">ABA-339</issue>), retargeted at the filter's stdout. Keep the existing watch-mode orchestrator tests green; assert the pane pipeline now includes the formatter stage.

## Acceptance criteria

* Running drain-cycle in watch mode inside tmux shows human-readable activity in the pane (turns, assistant text, tool calls and result sizes, done footer) — not raw JSON.
* drain-cycle's usage, cost, and breach accounting is unchanged: the FIFO still carries unmodified stream-json; numbers match the non-watch path exactly.
* No intermediate log file is reintroduced — the formatter is a live pipe stage.
* If the formatter cannot start, the drain does not crash and parse fidelity is unaffected (pane may fall back to raw JSON).
* Formatter has unit tests covering text, tool_use, tool_result, and result events; watch-mode orchestrator tests still pass.

## Estimate

Small — a few hours. The formatting logic already exists and was tested; the new work is converting it to a stdin-to-stdout filter, wiring one stage into the pane pipeline (interpreter resolution plus unbuffered output), and restoring and retargeting the tests. Risk areas: interpreter resolution inside the pane shell for the editable uv-tool install, and ensuring the filter does not buffer.
