# OTel `drain.issue` span carries new run-log fields as attributes

## What

The `drain.issue` OTel span emits attributes corresponding to the four new run-log fields: flow, outcome_verdict summary, prep_verdict summary, and responder run count.

## Why

The operator inspects drain runs in Honeycomb; without these span attributes, the new roles are invisible to the observability layer and the operator cannot distinguish verify-flow runs from default-flow runs in traces.

## Assumptions

* OTel attribute naming follows the project's existing `drain.*` namespace.
* Complex objects (verdict, runs array) are serialised as flat key-value attributes or JSON strings — the existing pattern in the codebase is followed, not assumed.

## Key Risks

* OTel attribute naming for nested objects may differ from semconv expectations; the naming strategy must be verified against existing `drain.*` patterns rather than invented.

## Definition of Done

* A `verify`-labelled drain emits a `drain.issue` span with the four new attributes present.
* Honeycomb receives and indexes the new attributes.
* Existing `drain.issue` attributes are unchanged.
